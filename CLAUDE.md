# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
make lint        # run markdownlint on all .md files (respects .markdownlint.yml)
make fmt         # auto-fix markdownlint violations
```

Generate the interactive practice-test HTML for one or all languages:

```bash
python3 utils/build_practical_test_html.py          # all languages
python3 utils/build_practical_test_html.py en       # English only
python3 utils/build_practical_test_html.py ru       # Russian only
```

> `build_practical_test_html.py` delegates question extraction to `extract_question.py` (root-level, **not committed**). The HTML build will fail until that script is present.

PDFs are generated automatically by CI (`.github/workflows/markdown-to-pdf.yml`) on every push to `main` using `md-to-pdf` with `.github/workflows/pdf-style.css`. Never edit `pdf/` files directly.

## Repository Structure

This is a multilingual documentation repo — no application code, no tests.

| Path | Role |
|---|---|
| `guide_<lang>.MD` | Source-of-truth study guides (Part I theory + Part II domain notes + questions) |
| `pdf/guide_<lang>.pdf` | CI-generated; do not edit |
| `practical_test_<lang>.html` | Self-contained interactive practice exams; generated by `utils/build_practical_test_html.py` |
| `.github/workflows/markdown-to-pdf.yml` | CI: converts all `guide_*.md` (case-insensitive) to PDF and commits back |
| `utils/build_practical_test_html.py` | Builds the HTML practice UIs; inlines all CSS/JS — no external dependencies at runtime |

## Content Architecture

Each guide file follows a fixed structure:

1. **Exam overview** — format, 5 domains with weights, 8 scenarios
2. **Part I: Theory Foundations** — 13 chapters organized by technology (API → Tools → Agent SDK → MCP → Claude Code → Prompt Eng → Batches → Decomposition → Escalation → Errors → Context → Provenance → Built-in Tools)
3. **Part II: Exam Domain Notes** — same content reorganized by the 5 exam domains, with explicit "key knowledge" and "key skills" bullets
4. **Sample questions with explanations** — 12 annotated questions
5. **Practice Test** — 76 questions across 4 scenarios, same format as the real exam
6. **Practical Exercises** — 4 hands-on exercises (one per major domain)
7. **Appendix / Out-of-Scope / Prep Recommendations**

## Adding a New Language

1. Create `guide_<lang>.md` at the repo root following the same structure as `guide_en.MD`.
2. Add the lang + title to `LANG_TITLES` in `utils/build_practical_test_html.py`.
3. Push to `main` — CI auto-generates `pdf/guide_<lang>.pdf`.
4. Run `python3 utils/build_practical_test_html.py <lang>` to generate the HTML practice test.

## Markdownlint Rules

MD013 (line length), MD033 (inline HTML), and MD060 (table column style) are intentionally disabled — spec tables use mixed alignment and some content requires inline HTML. Run `make fmt` before committing any guide edits.
